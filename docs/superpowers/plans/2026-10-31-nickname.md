# 昵称（微信式自报名）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让每个人能设置一个别人也看得到的昵称，并在会话列表、聊天页、通讯录、群成员名单与群标题里按「备注 > 昵称 > 身份缩写」显示。

**Architecture:** 昵称走两条已有的加密通道：单聊用 SCS-1 帧（新信封类型 `0x06`），群聊用 MLS 私密消息（新类型 `0x07`）。本机新增一个「名字簿」（身份 → 昵称），联系人记录增加一个**不落盘**的派生字段 `peerName` 承接显示优先级。服务器零改动。

**Tech Stack:** Kotlin（`:core` 纯 JVM / `:app` Compose）、Go（`protocol/mobile`，gomobile → AAR）、JUnit、Go testing。

**Spec:** [docs/superpowers/specs/2026-10-31-nickname-design.md](../specs/2026-10-31-nickname-design.md)

## Global Constraints

- 昵称**不得**进入预密钥目录、握手明文、服务器可见的任何字段。
- 显示优先级固定：`备注 > 昵称 > 身份缩写`。
- 昵称清洗：去 ISO 控制字符、`trim`、上限 **64** 字符（`ContactCodec.MAX_NICKNAME_LENGTH`）。
- 载荷格式固定为 `SCHAT-NICK-1\n<base64(UTF-8)>`；整段 ≤ 256 字节；未知版本丢弃。
- 信封类型：`0x06` = 单聊昵称通告，`0x07` = 群昵称通告；**不得与 `0x01/0x03` 混用**。
- 不改服务器（`server/` 一行不动）；不新增第三方依赖。
- 文件行尾 LF；界面文案中文、无 emoji、无渐变/阴影。
- 群消息：**先持久化 `nextGeneration`，再发送**；发送失败也不回退。
- 任何 `protocol/mobile` 导出面变化后必须重建 AAR，否则 Kotlin 报 `Unresolved reference`。

## Review Focus

1. **昵称里的换行/制表符/双向覆盖字符**：写入名字簿或联系人后不得伪造出第二条记录；显示不得被反转成别人的名字。
2. **7 字段的旧联系人记录**：升级后必须仍能解码，否则联系人列表会整体消失。
3. **信封类型混淆**：`0x06` 不得被当作 `0x03` 解密、`0x07` 不得被当作 `0x01`；错类型必须报错而不是交回载荷。
4. **回执错位**：昵称通告不占「待确认投递」位时，它的回执会把前一条聊天消息误标为「已送达」。
5. **群里陌生成员的昵称**：昵称到达时对方可能不在联系人里，必须仍能显示并在之后转为联系人时保留。

/**

fun saveGeneration(groupIdHex: String, generation: Long) {
